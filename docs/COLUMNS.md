Статус: **часть 1 сделана** (ядро без Revit + тесты), **часть 2 — на ПК с Revit**.

## Решения

- **Хранение — вариант А.** Армирование лежит на каждой 3D-колонне. Колонна с другим значением —
  новая строка в таблице (новый «тип»).
- **Семейства** лежат на ПК: `C:\Users\user\Desktop\Families Dima\04 Rebar\2D Rebar\Column Reiforcement`.
  Работать только с **копией** папки, оригиналы не трогать.
- **Норма** ת"י 466: PDF / пункты присылает пользователь. До этого правила = логика старого скрипта.

## Что сделано (часть 1)

`lib/column_rebar/` — чистый Python, миллиметры, работает в IronPython 2.7 и CPython.

| Модуль | Что делает | Откуда в старом скрипте |
|---|---|---|
| `rules.py` | число стержней, размер хомута, количество шпилек, список поперечной арматуры сечения | `script.py:586`, `1159`, `1586` |
| `grouping.py` | группы колонн, слияние и разбиение строк, марки и диапазоны марок, дубли марок | `script.py:55`, `424`, `775`, `944` |
| `layout.py` | точки вставки сечений по реальным габаритам, без наложений | вместо шага 2 м (`script.py:1137`) |

Тесты: `py -3 -m unittest discover -s lib/column_rebar/tests` — 28 тестов, числа фиксируют
текущую логику. Старый `script.py` пока **не тронут** и этими модулями не пользуется.

Что изменено по сравнению со старым скриптом (намеренно):
- ключ группы округляется (0,1 мм), шум перевода единиц не дробит группу;
- марки сортируются без сравнения числа со строкой (старый код падал бы в CPython);
- раскладка считает габарит сечения с хомутом, шпильками, тегами и номерами марок.

## Что не так в старом скрипте

1. Вид очищается **до** проверки семейств: нет Shape 62 — параметры уже записаны, вид пуст (`script.py:1020-1109`).
2. 4–5 отдельных транзакций, Undo по кускам.
3. Семейства не догружаются из библиотеки (`peer_library.require` не используется).
4. Группа с нечитаемым B/H не чертится, не попадает в отчёт, но считается начерченной (`script.py:1400`, `1804`).
5. Колонны и документ читаются один раз при запуске, окно немодальное — данные устаревают, кнопки Refresh нет.
6. У скруглённой с двух сторон (ROUND2) нет хомута (`script.py:1589`).
7. Ø хомута, Ø шпильки, слой, ширина листа, имя вида не хранятся и одни на весь уровень; шаг 200 зашит.
8. Правила разбросаны: формулы семейства (`Rebar_SpacingX/Y`, `HasVerticalSpacer`, `HasHorizontalSpacer`), скрипт, зашитые числа.
9. Из файла `Идеи` не сделано: два хомута для больших колонн.
10. В поставке лежит мусор: `OLD/`, `.idea/`, `__pycache__/`, `Thumbs.db`, `Create Col Formula.txt`.

  Qb касательных стержней не содержит — похоже на ошибку. Решить в п. 8.
- **Шаг стержней.** Правило 150 мм берёт шаг из семейства (`Rebar_SpacingX/Y`). `rules.estimate_spacing`
  — запасной расчёт для прямоугольной; сверить с формулой семейства в п. 7.
- **150 мм — по осям или в свету?** Сейчас сравнивается то, что отдаёт семейство. Уточнить по норме.

  оценка, проверить на листе.
