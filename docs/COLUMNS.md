## Решения

- **Хранение — вариант А.** Армирование лежит на каждой 3D-колонне. Колонна с другим значением —
  новая строка в таблице (новый «тип»).
- **Защитный слой c — до хомута** (решение пользователя 20.11.2026, как в руководстве): хомут габаритом
  (b − 2c) × (h − 2c), ось стержня = c + Ø_хомута + Ø/2. В семействах-копиях (п. 12) `Cover` переделать
  так же; старые колонны с Cover 25 получат стержни на Ø хомута глубже.
- **В колонне — внутренние хомуты всегда, где есть пара** (решение пользователя 20.11.2026), хотя по стали
  дороже шпилек (~+14 % на 800×800): режим `AUTO`. Шпильки — для нечётного среднего и в пилоне.
- **Решения по большой проверке** (пользователь 20.11.2026, проверено повторно — 66 из 67 без замечаний, картинки
  `tests/out/check4`):
  - грань, где правило требует закрепить один из двух симметричных стержней (4 на грани), — шпилька **вразбежку**:
    на одном стержне сплошная, на зеркальном пунктиром (по высоте через раз); в стали считается одна;
  - внутренний хомут — **как есть** (рядом скрипт нарисует сами изделия, будет понятно);
  - шпильки **как в семействах пользователя** (Klamrot 2d > Rebar_Shape 61; после замечания «линии через центры
    стержней, крюки плохие»): линия идёт по касательной к стержням (R = (Ø + Øхомута)/2 от осей), крюк — полуокружность
    вокруг стержня и прямой отгиб назад C = max(50 + 2Ø, 7Ø) хомута; у V-образной ноги по касательным снаружи, вершина —
    дуга вокруг среднего стержня, крюки на концах с отгибом вдоль ноги (`family_ties.py`). Хвостики 135° отменены;
  - скруглённая с одной стороны, 2+ стержня плоского торца — **внутренний хомут на пару** от торца до первого
    ряда боковых стержней (места HoopT1–2), нечётный средний — V-образная шпилька.
- **Семейства** лежат на ПК: `C:\Users\user\Desktop\Families Dima\04 Rebar\2D Rebar\Column Reiforcement`.
  Работать только с **копией** папки, оригиналы не трогать.
- **Норма** ת"י 466: правила офиса — документ «Армирование колонн по ת"י 466 / ת"י 413 — руководство и
  чек-лист» (https://claude.ai/artifact/LsDNDGiTN5gdMsHQuXhhQv, 20.11.2026). Пункты: 466-2 28.6.1–28.6.2,

## Правила по норме (`code466.py`, 20.11.2026)

`code466.design(shape, b, h, cover, bar_dia, nb, nh, stirrup_dia=None, spacing=None, dense=None)` —
сечение по руководству: координаты стержней, какие закреплены, хомут, шпильки, запись «Ø8@250/100»,
список сообщений `RED` (выпуск нельзя) / `YELLOW` (проверить) — простым текстом, пункт нормы отдельно.
`code466.blocked(result)` — есть ли красное. Формы: `RECT` и `CIRCLE` (как в руководстве).
Тесты — `tests/test_code466.py` (19), в т.ч. пример руководства 400×600: Ø20 → Ø8@250/100, Ø12 → Ø8@175/100.

| Что | Было (старый скрипт, `rules.py`) | Стало (`code466.py`) |
|---|---|---|
| Ввод числа стержней | на сторону **без** 4 угловых (`qb`, `qh`) | вдоль b и вдоль h **с** угловыми; `from_old_counts` переводит |
| Ø хомута | ввод, по умолчанию 8 | max(6; Ø/4) → ряд 8, 10, 12…; меньше — красное |
| Ø шпильки | ввод, по умолчанию 10 | = Ø хомута; толще продольного — красное |
| Шаг хомутов/шпилек | 200, зашит | S = min(b_c; 16Ø; 250), S₁ = min(0,6S; 100), вниз до 25 |
| Где шпильки | шаг из семейства > 150 → на каждый стержень, иначе через один | по фактическим координатам: незакреплённый ≤ 150 от закреплённого, закреплённые ≤ 300 (по осям), минимум шпилек, из равных — симметричный |
| Угловой стержень | — | сидит в дуге гиба хомута (оправка 4Ø / 7Ø) |
| Проверки | нет | 16 пунктов чек-листа: Ø ≥ 12, число ≥ 4 / 6, 0,4–0,8–4 %, зазор ≥ max(35; Ø), 150/300, хомут помещается, «это стена» |

На типовых колонках (600×600 5×5 Ø16; 800×800 4×4 Ø25) число шпилек по новому правилу совпало со старым.
Старый `script.py` и `rules.py` по-прежнему **не тронуты**; переход — в п. 10.

## Чем держать промежуточные стержни: шпильки, внутренние хомуты, V-образные шпильки

Просьба пользователя 20.11.2026 (эскизы 800×800 и пилона 1200–1500 × 600–800). Норма (466-2, 28.6.2)
допускает замкнутые и открытые дополнительные хомуты; выбор — практика офиса. `design(..., transverse=...)`:

| Режим | Что делает |
|---|---|
| `AUTO` (по умолчанию) | **колонна** (длинная/короткая ≤ 2): соседние закрепляемые стержни грани — парами во внутренний замкнутый хомут (две шпильки → один хомут), нечётный средний — шпилькой; **пилон** (> 2): поперёк короткого размера — шпильки, средний стержень короткой грани — **V-образная шпилька** до ближайших стержней длинных граней, где угол у вершины ≤ 135°, и **прямая шпилька** между её концами (эскиз пользователя: «две шпильки — V-образная и прямая»); стержни на концах V считаются закреплёнными |
| `TIES` | только шпильки |
| `HOOPS` | внутренние хомуты везде, где есть пара |

Что закреплять, решает по-прежнему правило 150/300; режим меняет только, чем держать. В результате
`hoops` (`rect`: пара стержней и габарит), `ties` (`straight` или `v`: три точки и угол у вершины) и `set_length` — сталь
поперечки на один комплект. Примеры: 800×800 4×4 Ø25 — шпильками 6,63 м, хомутами 7,59 м (+14 %);
пилон 1500×600 7×3 — авто (V + прямые) 9,31 м, только прямыми 9,08 м, хомутами 10,01 м. Длины крюков — оценка (20Ø на изделие).

## Скруглённые формы ROUND1 / ROUND2 (`code466._rounded`, 20.11.2026, правило — на согласовании)

Геометрия как в семействах: b — короткая сторона = диаметр скругления, h — длинная; ROUND2 — полукруги на
обоих концах, ROUND1 — полукруг сверху, снизу плоский торец с углами. Счёт как в легенде семейств:
`nb` — стержней на каждом торце без боковых, `nh` — на каждой длинной стороне вместе с крайними
(`Rebar_QuantityX/Y` без пересчёта). Хомут повторяет контур.
- Стержни на скруглении и крайние стержни длинных сторон держит изогнутый хомут (как в круглой колонне);
  по дуге ≤ 300 мм, иначе красное «добавьте стержни на торце».
- Средние стержни длинных сторон — правило 150/300, держатся поперёк b: в колонне (h/b ≤ 2) внутренними
  хомутами парами, в пилоне — шпильками (короткие, поперёк).
- ROUND1, плоский торец: углы держит хомут; один средний стержень, которому нужно закрепление, — V-образная
  шпилька к боковым стержням (угол ≤ 135°) и прямая шпилька между ними; больше одного — жёлтое «закрепить вручную».
- Площадь бетона — с вычетом скруглений. Если h < b — красное.

### Контур скруглённой колонны — два варианта (21.11.2026, решение пользователя)

Выбор — в окне по строке (столбец «Rounded contour») или параметром 3D-колонны `Rebar_Contour`
(Split / One, общий, `column_params.txt`); по умолчанию — **Split**:
- **Split** — прямоугольный хомут по прямой части (между рядами касания скруглений; у ROUND1 — до плоского
  торца) + полукруглая пешка на каждом скруглении (ROUND2 — 2, ROUND1 — 1). Ноги пешки от линии центра дуги —
  нахлёст **40Ø хомута**, вверх до 10, но не длиннее прямой части (короче — жёлтое `u_leg`).
- **One** — один хомут по контуру: ROUND2 — овал (Shape 65), ROUND1 — Shape 60.
`code466`: `contour=`, в `stirrup` — `contour`, `rect {a, b, length}`, `u {a, leg, b, count, length}` (размеры
наружные, как у Shape 52/60); `slots`: `Contour_Split`, `U_Leg`. В сечении (`family_section`) — вложенные
`PEER_Col_Hoop` (прямоугольный) и `PEER_Col_URound` (новое, `family_build.build_u_hoop`) по `Contour_Split`,
прежний хомут по `not(Contour_Split)`; пешка рисуется на Ø хомута снаружи — нахлёст виден двойной линией.
Проверка: 37 скруглённых сечений `revit_check` — 0 замечаний; `revit_e2e` — обе формы контура.

Новые 2D-формы для таблиц (`family_shapes.py`, из копии Shape 60, подписи и параметры те же, + густой шаг):

## Что решают семейства (разбор копий 20.11.2026)

Копия: `Families Dima\04 Rebar\2D Rebar\Column Reiforcement (work)` (+ Shape 52 / 60 / 62). Все три
`Create Column*` — Detail Items, без типов, внутри два вложенных: **PR_Column Reinforcementr** (стержни)
и **Klamrot 2d** (шпильки внутри сечения, вложенный `Rebar_Shape 61 Not Shared`).
Общие параметры (GUID): `PR_Dimension_Width` 8f2e4f93…, `PR_Dimension_Height` da753fe3…,
`Rebar_Diameter` 5498ba20…, `Rebar_QuantityX` de7637e2…, `Rebar_QuantityY` 79cc3e37…,
`Rebar_Quantity` 9f1fd3ff…, `Rebar_Number` 3daaa3a8…, `Rebar_Spacing` 84bfe62c….

Решения в формулах:
- **`Cover` — слой до СТЕРЖНЯ, хомут не учтён.** Прямоугольная: ось стержня = `Cover + Ø/2`; скруглённые:
  `Cover + Ø` (иначе, чем у прямоугольной). Старый скрипт рисует хомут габаритом `B − 2·Cover` — стержни
  ложатся на линию хомута. В `code466` слой до хомута, ось = c + Ø_хомута + Ø/2 (как в руководстве).
- **Шпильки (Klamrot 2d)**: шаг по осям ≤ 150 → через один: (n−2)/2 при чётном n, (n−3)/2 при нечётном
  (n — стержней на сторону с угловыми); > 150 → на каждый промежуточный. Одиночная горизонтальная шпилька
  рисуется только при B > 390. Параметры хоста `HasVerticalSpacer` / `HasHorizontalSpacer` (сторона > 400)
  во вложенное не передаются — их читает только скрипт.
- `Rebar_Spacing` (общий) = `(H − 80 мм)/(Qy + 1)` — число без смысла (80 зашито), уходит в таблицы.
- Shape 52 (хомут): длина = roundup((2(A+B) + 20Ø)/50)·50. Shape 60: **`Rebar_Shape` = 52 (ошибка, должно 60)**.
  Shape 62 (шпилька): крюки C = max(50 + 2Ø, 7Ø) вверх до 10.

Сравнение шпилек на одну сторону (Ø20, слой 25; таблица — `compare_old.py`):
- **старый скрипт ≠ семейство при чётном числе промежуточных** (n = 4, 6): скрипт считает
  ceil(q/2) − 1, семейство — q/2; в таблицу уходит на одну шпильку меньше, чем нарисовано;
- **семейство нарушает 300**, когда промежуточных мало: 2 стержня на стороне ≥ 400, 3 на ≥ 700, 4 на 1000 —
  в `code466` это красное «добавьте стержень»;
- там, где правило выполнимо, `code466` ставит столько же шпилек или меньше (500/7, 600/7: 1 вместо 2);
  иногда на одну больше из-за другой геометрии (стержни сдвинуты внутрь на Ø хомута).
