# PEER Feedback — one page for the team

Two buttons on the **PEER** tab, panel **Feedback**.

## Contact — ask, suggest, report a bug

1. Click **Contact**.
2. Pick a topic:

   | Topic | When |
   | --- | --- |
   | Automation | "I want a button that…" |
   | Improve a button | an existing button is awkward — pick it |
   | Bug | a script crashed or gave a wrong result |
   | Idea | a process suggestion, not only scripts |
   | Routine | "I keep doing this by hand" |
   | Template & families | a family, type or parameter is missing |
   | How-to question | not clear how to do something |
   | Office standard | a rule is unclear or inconvenient |

3. Write what you need in a few sentences. **How often** and **Time per
   occurrence** are optional, but they decide what gets automated first.
4. A picture says more: take a screenshot (Win+Shift+S) and press
   **Ctrl+V** in the window, or drop image files on it. Up to 5.
5. **Send** (or Ctrl+Enter).

**Bug in one click:** when a PEER button fails, click **Contact** right
after — the topic, the button and the error are already filled in. Add a
line about what you were doing if you can, then **Send**.

Works at the office and at home. No internet? The request is saved and
goes out automatically on the next Revit start.

## My Requests — what happened to them

Shows your requests and their status: **New → Accepted → In progress →
Done** (or **Rejected**, with a reason in the comment). Every request
gets a status within a week.

## What PEER collects

- With a request: your text, the project and view name, the categories of
  the selected elements, Revit / pyRevit / PEER versions.
- Every day: how many times each PEER button was run and how many runs
  failed. Only PEER buttons — not what you do in Revit.
- Pictures only when you add them yourself.
- Never: model files, geometry, parameter values.

Results are looked at for the group as a whole, not per person.
